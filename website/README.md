# Brundlefly website

Self-contained Agent Skills focused on empathy and accessibility in writing.

The site introduces the Skills and offers complete downloads.
Its mascot conversation uses Cloudflare and OpenAI. It does not execute a Skill.
The site uses Nuxt, Nuxt UI, and the canonical brand artwork.

## Develop

```sh
cd website
pnpm install
pnpm dev
```

## Check

```sh
pnpm check
```

Nuxt generates static HTML, browser scripts, and self-hosted fonts.
The Cloudflare Vite plugin packages that output as an assets-only Worker.
The empty client entry satisfies Vite's build requirement. Nuxt supplies the actual browser application.

## Preview Cloudflare

After building, run:

```sh
pnpm preview:cloudflare
```

## Deployment

The Website workflow is the production deployment path.
It deploys the brundlefly Worker when website, brand artwork, or Skill changes reach main.
Configure CLOUDFLARE_API_TOKEN and CLOUDFLARE_ACCOUNT_ID as repository Actions secrets.
Give the token Workers Scripts Write and Account Settings Read for the intended account.
Give it Workers Routes Write and Zone Read for the brundlefly.dev zone.
The custom domain is brundlefly.dev in cloudflare.config.ts.
Pull requests run checks. Main builds deploy after those checks pass.
Deployment runs finish before another main build starts.
The workflow checks live pages, browser scripts, scene artwork, models, and Skill downloads against the build.

To rerun the current main deployment, use the Website workflow's manual dispatch.
To check an existing build against a host, run:

```sh
node scripts/verify-deployment.ts https://brundlefly.dev
```

## Brand and copy

Edit canonical artwork in the root assets/brand directory.
The sync script copies the banner and avatar before development and builds.
DESIGN.md owns website tokens. COPY.md owns website strings.
Root GLOSSARY.md, VISION.md, and brand rules remain authoritative.

Nuxt's [static export](https://nuxt.com/docs/4.x/getting-started/deployment) feeds
Cloudflare's [Vite asset packaging](https://developers.cloudflare.com/cf/projects/cloudflare-config/).

The build also creates ZIP downloads with each complete skill directory and its license.
Visitors can download the skills without GitHub access.

The [brand kit](../docs/brand/kit.md) lists all artwork and defines the task-first workspace.
The [generation prompts](../assets/prompts/brand-kit.json) record references and exact prompts for the three new artifacts.
The sync script also copies these materials into the static site.

## Precomputed conversation replies

The first three selected exchanges use replies generated by GPT-6 Luna.
The generator uses the same canonical prompt, model settings, Gateway, and output parser as live dialogue.
Replies retain speech, movement, mood, three visitor choices, and Skill or brand kit links.
The browser loads the generated replies with the site. Selected preset replies need no API request.
A 200 ms pause gives him a brief breath before each cached reply. Closing cancels that reply.
The greeting still receives its verified visitor count from the server.
Typed messages and choices beyond the generated depth use the live dialogue API.
If a choice needs the visitor's sentence or personal details, it opens the existing text field.

To regenerate replies, start the local AI binding in one terminal:

```sh
pnpm presets:serve
```

Then generate replies from another terminal:

```sh
pnpm presets:generate
```

Review `shared/dialogue-presets.generated.json` before committing it.
Generation checkpoints stay in `~/scratch/brundlefly-dialogue-presets`.
Set `BRUNDLEFLY_PRESET_SCRATCH` to choose another checkpoint directory.
The generator uses remote inference and consumes Gateway credits. It uses no production visitor records.
It runs on loopback only. The production build excludes its entrypoint.

Run `pnpm presets:check` to check source hashes, complete branches, input choices, links, and movements.
The test command includes this check. Prompt, model, settings, and opening changes require regeneration.
The graph records the Skill catalog used during generation.
If that catalog changes, replies containing Skill links use live generation until the graph is regenerated.
Character replies keep using the cached graph. Every saved link must still exist in the current catalog.

## Present the office experiment

The projector and attendees share one specimen counter. A Durable Object holds the count and sends it to every device.
One tap adds one specimen. At the target the room goes critical for everyone, and the scene moves them to the cave.
The experiment uses `/projector` and `/join`. The public office at `/office` keeps its usual conversation and travel.

1. Open `/presenter` on your own device. Choose **Reset experiment**, then set the target. The page is public. For a test alone, choose the quick target of 10.
2. Open `/projector?show` on the projector for the full one-clicker act (five PenGPT pen-and-ink notebook slides, smooth fade into the 3D office, glowing beetle QR code, and blackout reveal), or `/projector` for the office alone.
3. The audience scans the QR code on Slide 5 or on the glowing beetle glass. It opens `https://brundlefly.dev/join`, which puts each phone at the desk computer. The address is also shown in letters.
4. Each key adds one specimen. The whiteboard, the computer screen, and the presenter page show the count. From 80% of the target the chamber is unstable: its warning light turns faster and throws red on the room, the room shakes now and then, and the tubes dip. From 90% all of that is stronger, and the computer warns.
5. At the target, phones lock on the **CHAMBER OVERLOAD / LOOK UP NOW** alarm so every eye snaps to the room. Green arcs leap from the chamber, the chamber spits out snails, and the projector fades to pitch black and holds with a rising hum pulse.
6. When ready, press **Next** on the presenter clicker (or **Reveal cave now** on `/presenter`). The celebration track swells for 4 seconds in the dark, and the cave snaps in with dancing snails on the chorus drop. Phones unlock an **Enter the 18th Dimension** button after the reveal.

If the room is slow, **Go critical now** on the presenter page starts the scene at the current count.
The initial target is 800. Change the target at any time; the count stays.
The room accepts 20 taps a second from one device and drops the rest.
A critical or revealed run clears itself after 30 minutes. A counting run clears itself after two hours with no tap.
A phone that came by the join code starts with the sound off.
The experiment shows its cave on the same page. After finishing, visitors can travel between the cave and office there.

To tune the join code for a projector, open `/projector?tune` and select the chamber window.
The up and down keys change how solid the glass is. The left and right keys change how bright the beetles are.
`?glass=` and `?bugs=` set both values from the address, each from 0 to 1. Test each look with a phone before the talk.

### The celebration in the cave

When the cave appears, Brundlefly and the snails dance. A song can play on the projector.
The site ships no song. On `/presenter`, in the browser that drives the projector, choose your own audio file under **Celebration track**.
The file stays in that browser's storage. It is never uploaded, and **Remove track** deletes it.
A new track takes the defaults: chorus at 0:39.2, 124 BPM, 4 seconds of fade in, 22 seconds of play, and a fade out of 4 seconds.
For another song, set where the chorus starts and tap the tempo. Choose **Test from the fade** to hear the result: a cue turns solid at the moment the cave would appear.
When you trigger reveal from the blackout hold, the song swells for 4 seconds and its chorus hits on the exact beat the cave appears.
The room shares the tempo and the times with every device. Phones play no sound.
Before the talk, press a clicker key or select anything on `/projector` once. A browser plays no sound on a page that nobody has touched.

The local Cloudflare preview runs the Durable Object. It needs a Cloudflare login for the AI binding.
